# 角色步态与可走范围 · 视觉评审

用户要求：所有会移动的角色有明确迈步、重心和停步，不再僵直滑动；不可到达的墙壁和物件不能走过去或踩上；巡逻看守走到远端做望远镜观察动作。机器人外形保持现有设计。

按用户既定流程，本轮先交付动作与阻挡范围预览。尚未修改游戏中的移动、碰撞或巡逻逻辑，等待视觉确认后实现。预览不代表已在 Unity 运行。

## 动作

- 主角：脚跟接地、重心下降、经过、抬步，左右脚交替；手臂反向摆动。碰到阻挡或抵达目的地即停止步态，不原地空走。第一关缺腿时仍不能移动；恢复腿但缺手时保留单臂状态并使用交替腿动作。
- 看守：持灯有节奏巡逻、转身、停步；远端取出望远镜、举到眼前、观察、收回，再转身返回。警觉/钟声分心打断观察时先收镜，不能一边观察一边滑动。
- 囚犯等静态NPC不新增行走路线。老囚犯保留互动；看守依用户修正自主行动，不增加点击对话。
- 已完成的攀爬继续使用抓握与抬腿姿态，不以行走帧代替。

## 地面和碰撞

预览中的绿区代表建议可走的脚底区域，红区代表墙体或大型物件占地。它们用于确认布置，实际游戏不会显示这些辅助线。

阻挡按物件接地范围和角色脚底留出的间距判定，不把整张人物/物件图片当成地面障碍：站在机器前可正常遮挡，脚不能落到机器底座里。高处小孔和平台必须走梯子；门没打开前不能穿过。

修正路线优先规则：点击有效地面才移动；点到墙、机器或未连接区域时停在可到达的边界，不瞬移或穿越；点击可交互物件时走到它前方的合法站位。大障碍的另一侧如需绕行，应使用确实存在的地面通道。

后续实现将验收：六个区域脚底范围、全部交互站位、门与通风口状态、上下平台、不同步态帧与碰撞停止、看守举镜/收镜/被打断和重开复位。用户已授权在2026-11-05推送今日进度；本预览随进度归档，视觉确认后再修改Unity移动、碰撞和巡逻逻辑。
