# 机械城归途 · Scrap Return

一个 Unity 2D 点击解谜原型：三关连续可玩，从废料场装配身体，到城门伪装通过检查，再到据点气压机关。

用 Unity 2022.3 LTS 打开工程，载入 `Assets/Scenes/RobotEscapeDemo.unity`，点击 Play，从标题界面开始。

## 玩法流程

前三关可连续游玩：城外废料场 → 城门检查口 → 黑帽帮据点夹道 → 被捕牢房结尾。

基本操作：鼠标左键点击地面移动，点击物件会先走近；拾取物品后点击底部背包使用。Esc 退出当前调查或机关，右上角可重玩本关或返回标题。界面不提供常驻任务提示，线索靠场景里的可调查物件自己拼。

- **第一关 · 废料场**：真实的缺肢装配。没有腿就不能走，但可以摇动身边废料堆露出腿；拿到腿也不会自动装上。恢复行走后翻找另一只零件箱取得手臂，装回手臂才能操作气压轮——压力表、蒸汽与门三者联动。
- **第二关 · 城门检查口**：废弃帽子与外衣需分别拾取、穿戴，身上要可见制服；伪装不完整或未接受守卫检查都开不了门。合照、值勤画像和值勤簿是可选调查内容，不能替代通行检查。
- **第三关 · 据点夹道**：气压平衡加滑块联锁用于安静开启偷听格栅。听完三段对话才可退开，解开机关后跳过剧情不能直接过关。
- 重开会完整复位部件、衣帽、机关与抓捕状态，不会残留上一局的进度。

第四关越狱及后续救援、塔顶拆弹、修复机器人、飞行器结局尚未制作。

## 技术实现

**运行时逻辑 1636 行 / 8 个脚本**

| 脚本 | 职责 |
| --- | --- |
| `RobotEscapeRoom.cs` | 关内状态与会话流程 |
| `ControlRoomController.cs` | 第三关的气压与滑块机关控制 |
| `WatchRoomController.cs` | 第二关的伪装与守卫检查 |
| `Room01Mechanism.cs` | 第一关的气压轮与压力联动 |
| `ScrapAssembly.cs` | 部件拾取与装配判定 |
| `SlideBlockHandle.cs` | 滑块拖拽与联锁 |
| `RobotWalker.cs` | 点击寻路与世界坐标移动 |
| `RoomInteractable.cs` | 统一的可交互组件（物件类型 + 站位点） |

**机关用显式状态标志单向驱动。** `PressureSolved` / `BoardSolved` / `ArchiveSeen` / `ExitOpen` / `PlotHeard` 等全部是只读属性，由输入事件单向推进；UI 与门体只订阅结果，不反向改状态。重开关卡时复位一次状态即可，不会出现"门开着但标记没清"的脏数据。

**交互先站位再触发。** 每个可交互物件上挂 `RoomInteractable`，绑定一个 `standPoint`；点击后角色先走到站位点，抵达才执行交互。这样从结构上排除了"隔着半张地图点门也能开"的情况，比事后加距离判断更稳。

**行走范围用矩形夹取。** `RobotWalker` 用 `minWalk` / `maxWalk` 两个角点定义可走区域，`MoveTo` 里直接 `Mathf.Clamp` 目标点，配合 0.025 的到达阈值判定 `IsMoving`。没有障碍寻路，这是刻意的简化——原型阶段先保证手感。

**场景由 Editor 脚本构建（2111 行 / 8 个脚本）。** `Assets/Editor/` 下的 Builder 按代码生成场景里的物件、UI 与图层，而不是手动拖出来的。好处是可复现、可批量重建：改布局改参数重新生成，不用一个个拖。重复的区域（三个房间的框架）用同一套构建逻辑套不同配置。

## 已知限制

- 没有跨关存档，重开会复位到本关初始状态。
- 行走区域是矩形，没有障碍寻路，走到墙边会贴边滑动。
- 中文 UI 使用本机 Microsoft YaHei 系统字体，跨平台发布前需换成可分发字体。
- 第四关及之后未实现。
- 编辑器里的 Builder 脚本是一次性生成工具，重复运行会覆盖已有布景，执行前先提交一次。
